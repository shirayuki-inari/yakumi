# LLM 断句与整句翻译：设计记录

> **状态：已实现（0.1.0）。** 这是实施前写的设计与计划，保留下来说明各项取舍；“背景”描述的是当时的规则断句和逐条翻译。
> 代码以 `src/yakumi/segment/`、`src/yakumi/translate/grouped.py`、`src/yakumi/subtitle/style.py` 为准，实测数据见文末。
> 实施时的变化：阶段名为 `segment`；同一句内不足 3 个字的碎片会并进相邻字幕条；翻译提示词增加了“原文是不可靠的识别结果”的说明；
> 后来增加的背景资料见 README“背景资料与补充说明”。

## 背景

当时的断句完全按规则：遇到句末标点、超过 0.6 秒的停顿、超出字数或时长上限就断开；**每条字幕单独翻译**。
在真实素材（76 分钟耳语 ASMR 直播，1107 条字幕）上的问题：

| 指标 | 数值 |
| --- | --- |
| 不在句末结束的字幕 | 58% |
| 时长不到 1 秒的字幕 | 58% |
| 3 个字以内的字幕 | 25% |
| 一句话被拆成 3 条以上 | 137 句 |

例：`音が | ちょっと | 微妙かな。`、`さっき | 確認してたときは | もうちょっと | いけてたんだけど。`

根本原因有两个：
1. **停顿不等于断句**。耳语说得慢，一句话中间常停 1～3 秒；识别给出的标点在口语里也不可靠
   （「今夜 / え、ASMRというのは / お帰りありがと叩くよ。」实际是两三句话，中间没有标点）。
2. **显示单位和翻译单位混在一起**。字幕条是显示单位，应该跟着时间走；翻译单位应该是完整的句子。
   日语和中文语序不同，把半句话单独翻译，很容易译错或不通顺。

## 目标

1. **LLM 断句**：按语义把识别文本切成完整的句子，修正识别遗漏的句子边界；**不允许改动任何文字**，
   时间戳仍然来自词级结果。
2. **整句翻译**：以句子为单位翻译。一句话需要拆成几条字幕显示时，让模型把译文按原文的分段对应切开，
   每条译文对应同一时段。
3. **规则兜底**：模型改动了文字、格式不对、请求失败或使用本地后端时，退回规则断句或逐条翻译，保证流程不中断。

**不做**：让模型修正识别错字或补标点（会破坏“文字不变”的校验，以后可以作为单独的可选步骤）。

## 两层数据

| 层 | 含义 | 来源 |
| --- | --- | --- |
| 句子（翻译单位） | 一个完整的意思，包含若干词 | LLM 断句（或规则） |
| 字幕条（显示单位） | 屏幕上同时出现的一段文字，属于某个句子 | 在句子内部按停顿、字数、时长拆分 |

- `Segment` 增加字段 `group: int`（所属句子编号，默认 -1 表示未分组）。导出格式不受影响，旧数据可以正常读取。
- 新产物 `sentences.json`：`[{id, start, end, text, word_range: [i, j), source: "llm" | "rules"}]`。
- `aligned.json` / `translated.json` 仍然是字幕条列表，每条带 `group`。网页编辑器继续按字幕条编辑。

## 流水线

```
… merge → repair → segment（新，替代 align）→ translate（改为整句）→ write → burn
```

- 阶段 `align` 改名为 `segment`，`PIPELINE_VERSION` 升到 4。
- **迁移**：版本 3 的任务载入时，只把 `align` 及之后的阶段标为未完成，**保留识别、合并、复核的结果**，
  不需要重新识别（目前版本不一致会清空全部识别缓存，这里改为按版本做有针对性的迁移）。

## 第 1 项：LLM 断句（`segment/llm.py`）

### 分块
- 把词序列切成约 `chunk_chars`（默认 400 字，拉丁文字约 250 词）的块，切在“强边界”上：
  句末标点后接 ≥ 1 秒的停顿，或任意 ≥ 2 秒的停顿。块与块互不依赖，可以并发（默认 4）。
- 找不到强边界时，在上限附近最长的停顿处切；块末尾那句话的完整性由下一步“跨块合并”检查兜底：
  如果某块最后一句没有句末标点、且离下一块的第一个词不到 1 秒，就把两句并成一句。

### 提示词与输出
- 把一块的文本按原样拼接（中日韩文字之间不加空格，拉丁文字之间加空格）发给模型，要求：
  每行一句；只在句子之间换行；**不得增删或改写任何字符，包括标点**；语气词、感叹词可以单独成句；
  每句尽量不超过约 `max_sentence_chars` 字（默认 60），过长的口语长句可以在分句处断开。
- 只需要换行这一种输出，所以输出 token 大约等于输入，思考档位用 `low` 就够了。

### 校验与映射（核心不变量：文字一个字都不能变）
1. 去掉输入和输出中的所有空白和换行后比较：
   - 完全一致：直接把每个换行的位置换算成原文的字符偏移；
   - 只有极少差异（`SequenceMatcher` 相似度 ≥ 0.98，例如全角半角、省略号写法不同）：用 diff 的对应关系把换行位置映射回原文；
   - 差异更大：整块放弃 LLM 结果，改用规则断句，并记一次 `segment_fallbacks`。
2. 把字符偏移对齐到最近的词边界（换行落在一个词中间时，挪到离它更近的那一侧）。
3. 得到每句话对应的词区间 `[i, j)`，时间取首尾词的时间。
4. **最终校验**：所有句子的词区间首尾相接，覆盖全部词，没有重复，没有遗漏。

### 纯文本模式
对每个文本块做同样的 LLM 断句，再沿用 `text_to_segments` 把句子按字数比例铺到语音区间上。

### 规则模式（兜底，也可以在配置里指定）
沿用现有逻辑，只断句末标点；停顿不再作为断句依据，只用来拆分显示（见下一节）。

## 句子 → 字幕条（`segment/cues.py`）

在每个句子内部按显示需要拆分。规则作用在词上，所以时间是准的：
- 词之间的停顿 ≥ `cue_gap`（默认 1.2 秒）时拆开：说话停了，字幕也应该先消失；
- 超过 `max_chars × 2` 行字数或 `max_duration` 时拆开：优先在分句标点处，其次在离中点最近的词边界；
- 同一句内短于 `min_duration` 的碎片，和相邻字幕条合并（前提是合并后不超限、停顿不超过 `cue_gap`）；
- **不跨句合并**：保证每条字幕只属于一个句子。

## 第 2 项：整句翻译（`translate/grouped.py`）

### 请求格式
- 每个句子一行，句内的字幕条用分隔符 `¦` 隔开：`3|音が¦ちょっと¦微妙かな。`
- 要求逐行输出 `编号|译文`，句内用同样数量的 `¦` 分段：`3|声音¦好像有点¦微妙吧。`
  - 整句译文要通顺；每一段尽量对应同一时段原文的意思。语序不同、实在无法对应时，允许把内容放到相邻段里，但段数必须一致；
  - 只有一条字幕的句子不出现分隔符。
- 每批约 `batch_sentences` 句（默认 15 句，也限制总字幕条数不超过 40），并发和上下文规则与现在一致
  （并发时上下文只带前一批的原文）。

### 校验与兜底（逐级降级，保证译文和字幕条一一对应）
1. 编号齐全、每句段数和字幕条数一致 → 直接采用；
2. 不一致的句子整批重试一次；
3. 仍然不一致：对这一句单独请求整句译文（不要求分段），再按原文各段的字数比例，在译文的标点或词边界处切开；
4. 再失败：退回现在的逐条翻译。

每一级各自计数（`translate_split_fallbacks` 等），写进统计。

### 已有字幕的翻译（`yakumi translate x.srt`）
没有词级时间，不做 LLM 断句，只把连续的字幕条按句末标点并成句子（最多 6 条），再按整句翻译。

## 字幕标点惯例（导出时处理）

中文字幕通常不用逗号和句号：句中用空格代替，行尾直接去掉，否则会显得很重。问号、感叹号保留；
列举用的顿号保留。日文字幕也基本一样（句中用全角空格）。

**处理位置：只在导出时套用（`subtitle/style.py`），不改保存的数据。** 原因：
- 整句翻译和按比例切分译文都要靠标点找切点，提前去掉会让切分变差；
- 网页校对时看到完整的句子更容易判断译文对不对；预览字幕和导出文件用的都是处理后的结果；
- 不同的人和语言习惯不同，做成配置 `[subtitle] punctuation = "subtitle" | "keep"`，比写进提示词更可控。

规则（按文字判断语言：有假名为日文，有汉字无假名为中文，其他语言不处理）：

| | 中文 | 日文 |
| --- | --- | --- |
| 句中 `，。；`（含夹在中文里的半角 `, . ;`） | 换成一个空格 | `、。` 换成全角空格 |
| 行尾 `，。；、：` | 去掉 | 去掉 `、。` |
| `? !` | 统一为全角 `？！` | 不变 |
| 省略号 `...` `。。。` `…` | 统一为 `……` | 不变 |
| 引号、书名号、括号 | 保留，删掉紧贴它们的多余空格 | 同左 |

数字里的小数点（`3.5`）、英文句子不受影响。

## 网页
- 字幕校对列表里，同一句的字幕条之间用细线连起来，句与句之间留空，方便按整句校对。
- 编辑仍然按字幕条进行，保存逻辑不变。

## 配置

```toml
[segment]
mode = "llm"               # llm | rules
model = ""                 # 留空则使用 translate.model；base_url / api_key / routing 也沿用 [translate]
reasoning_effort = "low"   # 断句任务简单，low 就够
chunk_chars = 400
max_sentence_chars = 60
concurrency = 4
cue_gap = 1.2              # 同一句内，停顿超过这么多秒就拆成新的字幕条

[translate]
unit = "sentence"          # sentence（整句翻译，按字幕条分段）| cue（逐条翻译，即现在的方式）
batch_sentences = 15
```

## 代码结构

- **新增**：
  - `llm.py`：从 `OpenAICompatTranslator` 中抽出通用的 `ChatClient`（请求、重试、思考档位、路由、用量统计），翻译和断句共用；
  - `segment/__init__.py`、`segment/llm.py`、`segment/rules.py`、`segment/cues.py`；
  - `translate/grouped.py`。
- **修改**：
  - `models.py`：`Segment.group`、`PIPELINE_VERSION = 4`；
  - `pipeline.py`：`segment` 阶段、版本迁移、整句翻译；
  - `translate/openai_compat.py`：改为基于 `ChatClient`；
  - `cli.py`：`translate` 命令按句分组；
  - `stats.py`：断句的请求数、兜底次数、费用；
  - `config.py`、`yakumi.example.toml`、README；
  - `web/static/job.js`、`style.css`：按句分组显示；
  - `subtitle/segment.py`：规则部分迁到 `segment/rules.py`。

## 实施顺序

1. 数据模型（`group`、`sentences.json`）、阶段改名与版本迁移；规则断句加句内拆分，先替换掉现在的 `align`，现有测试保持通过。
2. 抽出 `ChatClient`，翻译改为基于它，行为不变。
3. LLM 断句：分块、提示词、校验与映射、规则兜底、跨块合并。
4. 整句翻译：分段格式、校验、三级兜底；`yakumi translate` 按句分组。
5. 网页按句分组显示；统计、`doctor`、配置、README。
6. 在 ASMR 任务上验证（从 `segment` 阶段重跑，不需要重新识别）。

## 测试

- **文字不变**（核心不变量，在所有路径上检查）：断句前后，所有词的文本按顺序拼接后完全相同；
  所有字幕条的原文拼接后也和它相同。
- **映射**：模型输出与原文完全一致、只有少量差异（全角半角、省略号）、差异过大（回退规则）三种情况；
  换行落在词中间时对齐到最近的词边界；中日韩文字与拉丁文字。
- **分块**：块切在强边界上；并发后顺序不变；跨块合并生效。
- **字幕条拆分**：句内长停顿拆开；超长句按标点拆；短碎片在句内合并；从不跨句。
- **整句翻译**：段数一致直接采用；不一致时重试；按比例切分兜底；逐条翻译兜底；单条字幕的句子不带分隔符。
- **迁移**：版本 3 的任务载入后保留识别缓存，只重跑断句及之后的阶段。
- **假后端**：假断句按标点和固定字数断开；假翻译按段返回 `[zh] 原文`，用来跑通整条流水线。

## 验证（真实接口）

在 ASMR 任务上从 `segment` 阶段重跑，不需要重新识别。预计断句约 $0.05、翻译约 $0.2，共几分钟：
- 和现在对比：不在句末结束的字幕比例、短于 1 秒的比例、一句被拆成 3 条以上的数量；
- 抽查 20 句跨多条字幕的句子，对比逐条翻译和整句翻译的译文；
- 统计 LLM 断句的回退率（文字被改动的块所占比例）和整句翻译各级兜底的触发次数；
- 用前面那段英语有声书确认拉丁文字也正常。

## 实测结果（76 分钟耳语 ASMR 直播，日译中）

版本 3 的任务载入后保留了识别、合并和复核的结果，只重跑断句和翻译，共 2 分 28 秒。

| | 旧（规则断句 + 逐条翻译） | 新（LLM 断句 + 整句翻译） |
| --- | --- | --- |
| 字幕条数 | 1107 | 802（562 句） |
| 时长不到 1 秒的字幕 | 58% | 35% |
| 3 个字以内的字幕 | 25% | 8% |
| 一句话拆成 3 条以上 | 137 句 | 55 句 |
| 断句 | — | 20 块，回退规则 0 块，$0.026 |
| 翻译 | — | 41 次请求，分段重试 3 句，按比例切分 0 句，$0.166 |

“不在句末结束的字幕”从 58% 降到 40%。剩下的是同一句里按停顿拆开的字幕条，属于预期行为，这个指标已经不能衡量断句质量。

抽查 20 句跨多条字幕的句子：
- 整句翻译明显更通顺。例如 `もしかして | こよと近くて | ドキドキしちゃっていいんじゃないの。`，逐条翻译成了“心跳加速一下也是可以的吧？”，意思是错的；整句翻译为“你该不会心跳加速了吧？”，是对的。
- 语序不同时，偶尔会把内容挪到相邻的段里，例如 `ゲーミングふわふわ | いいよ。` → `那就选 | 电竞毛茸茸吧`。这在允许范围内。
- 人名和称呼前后不一致：こよ 被译成 小夜璃、小夜、Koyo；粉丝称呼 助手くん 被识别错成 ジョシュ君、じゃしくん，又被译成 乔希君、Josh君。加上背景资料后全部统一为 小夜璃、助手君（见 README “背景资料与补充说明”）。
